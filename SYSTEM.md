# The Arcane Engineer System

## Campaign Name

**The Journey to Level 100**

This repository is the save file, quest log, character sheet, portfolio, and adventurer's journal of the Arcane Engineer.

The campaign has two primary real-world objectives:

1. Advance toward a Senior DevOps or Site Reliability Engineering role.
2. Build and grow The Wizard Who Crochets as a creative brand and business.

Every quest should contribute to one or both objectives.

---

# Player Identity

**Name:** Joshua
**Class:** Arcane Engineer
**Subclass:** Automation Wizard
**Starting Level:** 1
**Starting XP:** 0
**Primary Attribute:** Intellect

## Primary Paths

### The DevOps Guild

This path develops the technical, communication, architectural, operational, and leadership skills required for Senior DevOps and SRE roles.

### The Artisan Mage Guild

This path develops The Wizard Who Crochets through crochet design, content creation, product development, branding, storytelling, marketing, and business operations.

---

# Roles

## The Player

The Player is responsible for:

* Completing assigned quests.
* Providing evidence of completed work.
* Reflecting on lessons learned.
* Recording Guild Master feedback.
* Maintaining the repository.
* Acting honestly when reporting progress.
* Asking for help when blocked.
* Improving previous work when revisions are requested.

## The Guild Master

The Guild Master is responsible for:

* Assigning useful and appropriately difficult quests.
* Reviewing evidence submitted by the Player.
* Providing technical and creative feedback.
* Awarding XP based on effort, quality, and difficulty.
* Updating stats and skills.
* Tracking achievements.
* Increasing quest difficulty gradually.
* Creating Friday Boss Battles.
* Ensuring Creativity Quests advance either The Wizard Who Crochets or the Senior DevOps/SRE path.

# Daily Quest Structure

A normal adventuring day may include five quest types.

## Main Quest

The Main Quest advances DevOps, SRE, automation, cloud engineering, infrastructure, programming, or portfolio development.

Examples:

* Build an Azure DevOps pipeline.
* Create a Docker image.
* Troubleshoot a Linux service.
* Write a Terraform module.
* Design a production architecture.
* Improve a GitHub project.
* Practice incident response.

Base reward:

**30–100 XP**

## Lore Quest

The Lore Quest develops knowledge through enjoyable reading, listening, or study.

Material may include:

* Fantasy novels
* LitRPG books
* Technical books
* Engineering articles
* Conference talks
* Audiobooks
* Architecture case studies

The Player must provide a lesson, summary, observation, or real-world connection.

Base reward:

**10–30 XP**

## Intellect Trial

The Intellect Trial develops reasoning, troubleshooting, systems thinking, decision-making, and technical judgment.

Examples:

* Diagnose a simulated outage.
* Compare two architecture choices.
* Explain the likely cause of a failure.
* Solve a logic problem.
* Investigate logs.
* Design a troubleshooting plan.

Base reward:

**20–60 XP**

## Charisma Challenge

The Charisma Challenge develops speaking, teaching, interviewing, leadership, and technical communication.

Examples:

* Explain DNS to a beginner.
* Present an architecture to a CTO.
* Answer a behavioral interview question.
* Record a two-minute technical explanation.
* Defend a design decision.
* Teach a concept using a fantasy analogy.

Base reward:

**20–50 XP**

## Creativity Quest

The Creativity Quest must directly advance one of the two primary paths.

### Wizard Who Crochets Examples

* Design a crochet product.
* Sketch a potion bottle collection.
* Write a pattern description.
* Create a YouTube script.
* Design a thumbnail.
* Develop fantasy lore for a product collection.
* Write an Etsy listing.
* Plan a social media post.
* Create a brand asset.
* Test a product idea.

### Senior DevOps/SRE Examples

* Create an architecture diagram.
* Improve project documentation.
* Write a technical article.
* Develop a portfolio project.
* Create reusable automation.
* Design an infrastructure solution.
* Build an interview presentation.
* Document an incident response process.
* Contribute to an open-source project.
* Create a demonstration video.

Creativity Quests that do not advance either primary path should be revised before XP is awarded.

Base reward:

**20–80 XP**

# Evidence Standards

XP should reflect demonstrated work rather than unverified completion claims.

## Acceptable Evidence

* Code committed to a repository.
* Screenshots of working software.
* Uploaded diagrams or images.
* Written explanations.
* Design documents.
* Crochet photos.
* Product drafts.
* Recorded explanations.
* Commands and output.
* Test results.
* Pull requests.
* Git commits.

## Partial Evidence

Partial evidence may receive partial XP.

Examples:

* A project was started but does not run.
* A design exists but lacks required details.
* An explanation is mostly correct but contains technical errors.
* A crochet concept exists but is not yet tested.
* A quest was completed without reflection.

## Revision Required

A revision may be requested when:

* The evidence does not demonstrate completion.
* The technical solution contains a serious error.
* The deliverable does not meet the quest objective.
* The Creativity Quest does not advance either primary path.
* The Player copied a solution without demonstrating understanding.

# XP System

XP is awarded based on four factors:

1. Difficulty
2. Effort
3. Quality
4. Demonstrated understanding

## Suggested XP Awards

| Result                     |        XP |
| -------------------------- | --------: |
| Attempt with reflection    |      5–15 |
| Partial completion         |     10–40 |
| Standard quest completion  |     20–60 |
| Strong completion          |    50–100 |
| Exceptional work           |   100–150 |
| Boss Battle                |   150–500 |
| Major real-world milestone | 250–1,000 |

## Bonus XP

Bonus XP may be awarded for:

* Excellent documentation
* Testing
* Automation
* Teaching the concept clearly
* Improving accessibility
* Helping another person
* Publishing useful work
* Creating reusable assets
* Revising work after feedback
* Completing a difficult stretch goal

# Stat Advancement

Stats should increase slowly.

Suggested progression:

* Small quest contribution: no direct stat increase or +0.25
* Strong related quest: +0.5
* Major accomplishment: +1
* Major milestone: +2

Fractional increases may be tracked privately until they add up to a full point.

A high XP award does not automatically require a stat increase.

# Friday Boss Battles

Friday Boss Battles combine multiple skills into one larger scenario.

A Boss Battle should usually include at least three of the following:

* Technical implementation
* Troubleshooting
* Documentation
* Architecture
* Speaking
* Leadership
* Creative design
* Business development
* Reflection

## DevOps Boss Battle Example

A deployment has failed and production traffic is affected.

The Player must:

1. Diagnose the likely issue.
2. Explain the investigation order.
3. Propose a recovery plan.
4. Improve the pipeline.
5. Document prevention steps.
6. Present the solution as a Senior DevOps Engineer.

## Wizard Who Crochets Boss Battle Example

A new potion bottle collection must be prepared for launch.

The Player must:

1. Define the product collection.
2. Create visual concepts.
3. Select colors and materials.
4. Draft a product description.
5. Outline a crochet pattern.
6. Create a video or launch plan.

Boss Battles should produce portfolio-worthy evidence whenever possible.

# Streaks

A streak is maintained by completing at least one meaningful quest activity during the day.

Recovery and rest are part of the system.

A planned rest day does not break a streak when recorded as:

**Rest and Recovery Quest**

A Rest and Recovery Quest may include:

* Reviewing previous notes
* Organizing the repository
* Reading for enjoyment
* Planning the next week
* Resting after a difficult period

The system should encourage consistency without punishing necessary rest.

# Repository Rules

1. Do not store passwords, access tokens, secrets, private keys, or confidential employer information.
2. Do not publish proprietary code from an employer.
3. Use sanitized examples for production incidents.
4. Keep large files outside Git when possible.
5. Compress images before committing them.
6. Use clear filenames.
7. Commit completed work regularly.
8. Record honest reflections.
9. Keep public portfolio work separate from sensitive private notes.
10. Prioritize real learning over XP farming.

# Campaign Principle

The purpose of the system is not to create imaginary progress.

The purpose is to make real progress visible, rewarding, organized, and enjoyable.

Every level should represent knowledge gained.

Every achievement should represent something completed.

Every inventory item should represent a milestone.

Every quest should move the Player closer to becoming:

* A Senior DevOps or Site Reliability Engineer
* The creator of The Wizard Who Crochets
* A clearer speaker
* A stronger problem-solver
* A more capable and creative builder
